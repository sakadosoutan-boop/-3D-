### 人間がやるべき判断 vs AIに任せられる作業

| 人間（あなた）にしかできない | AIに任せられる（今回整備した範囲） |
|---|---|
| 実機での体感評価（触り心地・音量・教育効果） | フィードバックの分類・修正・検証・コミット（/wave-feedback） |
| 教材としての内容判断（史実・教育的正しさの最終確認） | 静的検査・スモーク・ベンチ採取（npm run preflight） |
| アセットの美的判断・採否 | 軽量化・配置・命名・出典記録・接続（/asset-intake） |
| 公開（mainへのマージ）の最終GO | ブランチでの開発・PR準備・検証結果の整理 |
| ライセンス・権利の最終確認 | 記録漏れの検出（プリフライトが警告） |

## STEP 3: 優先順位

### 分類

- **今日すぐ作るQuick Win**: #1 波Skill, #2 FBテンプレ, #3 プリフライト, #4 アセットSOP → **すべて今回作成済み**
- **今後ずっと効く業務OS改善**: #5 CLAUDE.md, #6 /handoff, #8 ベンチ自動追記, #9 CI統合, #11 配布チェックリスト, #12 迷子アセット整理
- **Fable 5級の能力がある今こそ挑戦すべき高難度**: #7 ストーリー整合性チェッカー, #10 スモークのストーリー対応, #15 量産テンプレ, #16 データCSV往復

### 最初に着手した3つ（今回実装）と理由

1. **QA/プリフライト強化（#3）** — 他の全改善の土台。修正のたびに走る検証が1コマンドに揃っていないと、波SkillもアセットSkillも「直して壊す」リスクを抱えたままになる。
2. **実機フィードバック処理キット（#1＋#2）** — あなたにしかできない「実機で触る」時間を最大化し、それ以外（分類・修正・検証・コミット）を全部AI側に寄せる。日次で効くので累積効果が最大。
3. **アセット組み込みSOP（#4）** — 時間泥棒1位と回答された領域。加えて配布ゴールに直結する出典・権利記録を「後でまとめて」ではなく取り込み時に強制する仕組みが必要だった。
