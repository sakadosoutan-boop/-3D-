# 物語スタイルガイド & 品質ルーブリック — 御簾の向こうへ

最終更新: 2026-07-12
対象: `story/chapters/*.json` の全テキスト（本文・選択肢・独白・EDナレーション）
正本の世界観・人物・テーマは `STORY_SCENARIO_BIBLE.md`。本書は「どう書くか」の基準を定める。

このゲームは中堅進学校の高校生が古文・古典常識を「生き残るための作法」として学ぶ教材でもある。**文芸的な質と時代考証の正確さの両立**が品質の核心。新章の追加・既存章の改稿の前に本書を読み、公開前にルーブリックで自己採点する。

---

## 1. 文体規範（守るべき7原則）

1. **語り手の二重性を保つ**。主人公は現代の高校生・時任蓮であり、平安の若君・秀頼でもある。地の文には現代の視点（比喩・戸惑い・ツッコミ）を残し、会話・作法描写は平安の格を保つ。どちらかに振り切らない。
2. **説明を作法に変える**。用語解説を地の文で並べない。「格子（こうし）を上げる」ではなく、上げ方を間違えて女房に直される——など、動作・失敗・他者の反応を通じて名称と意味が入るように書く。教科書の文をそのまま置かない。
3. **美しさと怖さを同居させる**。ホラーの直接的describe（血・絶叫）に頼らない。「懐かしいのに帰れない」「雅なのに飲み込まれる」という反転で怖さを作る（バイブル中核テーマ3）。
4. **相手を記号にしない**。小萩・栞・女君を「かわいい」「守るべき」で消費しない。垣間見・恋愛パートでは「見えない相手を理想化する誘惑」自体を主題として扱う（バイブル中核テーマ2）。
5. **選択肢は人格の分岐にする**。正誤クイズではなく、現代人らしさ／雅への同調／世界への同化度を動かす選択にする。どれを選んでも「その人物なりの一貫性」が感じられること。明白な罠選択肢（露骨に破滅的な文）は避ける。
6. **隠しパラメータを言葉で説明しない**。realityEgo / fantasySynchro / brainErosion は、数値やゲージ名を本文に書かず、感覚描写（指先の冷え、声の遠さ、季節の匂い）で示す。
7. **一文の格を落とさない**。安易なネットスラング・過剰な顔文字・現代広告調は使わない。現代パートの口語は良いが、常世パートの品位を崩す語は禁止。

## 2. 時代考証チェックリスト（平安中期・寝殿造り）

新規テキストごとに確認する。1つでも不安があれば `docs/handbook/` の資料または国語科の一次資料で裏を取る。

- [ ] **建築・建具の名称と機能が正しい**（母屋・廂・簀子・格子/蔀・妻戸・御簾・几帳・帳台・塗籠・遣水・釣殿など）。図鑑データ `src/app/items.js`（ITEMS）の記述と矛盾しないこと。
- [ ] **官職・呼称・敬語の階層**が破綻していない（若君・北の方・女房・家司・乳母・命婦・随身など。身分差のある会話で敬語の方向が逆転していないか）。
- [ ] **和歌の扱い**：引用する百人一首・古歌は原典に忠実（`verify:html` がWAKA100首を検証）。creativeに詠む場合も、季語・掛詞・本歌取りが破綻しないこと。
- [ ] **年中行事・季節・時刻**が章設定と整合（章ごとに季節・時間帯が固定＝バイブル世界設定）。桜と紅葉が同一章に出るなどの矛盾がないか。
- [ ] **時代錯誤語がない**：武士政権以降・近世・近代の語彙、外来概念（分・秒の時計時間、科学用語）を常世パートで使っていないか。
- [ ] **固有名詞の読み仮名**：初出の難読語にふりがな（またはルビ相当の補助）があるか。教材としての可読性。
- [ ] **史実と創作の切り分け**：常世は「教科書＋想像＋未練」が作る半現実（バイブル）。史実を装った誤情報を教材として刷り込まないよう、明らかな創作要素は文脈で創作と分かるように。

## 3. 章品質ルーブリック（公開前に各項目を1〜4で自己採点）

| 観点 | 1（要改稿） | 2 | 3 | 4（理想） |
|---|---|---|---|---|
| **学習効果** | 用語が説明として羅列される | 用語は出るが体験と弱く結合 | 主要用語が作法・失敗を通じて入る | 遊んだ後に自然と名称・意味を説明できる |
| **文体の二重性** | 現代/平安のどちらかに偏る | 切替が不自然 | 概ね両立 | 二重性が物語の魅力になっている |
| **怖さの質** | 直接的・陳腐 or 怖くない | どちらか一方 | 反転の怖さがある | 美しさと恐怖が不可分 |
| **選択肢設計** | 正誤・露骨な罠 | 分岐はあるが人格が見えない | パラメータと人格が動く | どの選択も一貫し、後悔と発見がある |
| **人物の非記号化** | 相手が装置扱い | 一面的 | 内面が見える | 理想化の誘惑自体を描けている |
| **時代考証** | 明白な誤り | 数点の不安 | 概ね正確 | 一次資料水準で正確 |
| **接続の必然性** | ミニゲームが唐突 | 接続が弱い | 物語上の理由がある | モード移行が物語の山場になっている |

**合格ライン**: 全観点3以上、かつ「学習効果」「時代考証」は4を目標。2以下が1つでもあれば改稿。

## 4. 執筆・改稿のQAフロー

1. `STORY_SCENARIO_BIBLE.md` で該当章の人物・テーマ・季節設定を確認。
2. 本書§1〜§2に沿って執筆（`story/chapters/*.json`、スキーマは `story/schema/`）。
3. `npm run build:story` で本体へ同期 → `npm run build:story:check`。
4. `npm run verify:story`（章構造）と `npm run verify:routes`（ED到達性・ルートバランス）。
5. 本書§3ルーブリックで自己採点。2以下があれば2へ戻る。
6. `npm run smoke` まで通し、コミット（`feat:`/`fix:` ＋日本語要約）。

> 大きな章の新規執筆は、本書を渡した上で Opus のサブエージェントに委譲してよい（`/delegate`）。ただし**ルーブリック採点と時代考証の最終確認はオーケストレーター（上位モデル）が行う**——ここが品質の最終防衛線。
