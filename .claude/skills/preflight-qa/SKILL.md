# プリフライトQA

`寝殿造り3D探訪_統合版.html` の改修をpushする前の検証手順。

## 手順

### 1. 自動検査を回す

```bash
npm run preflight          # 静的検査 + アセット監査 + スモーク
npm run preflight:bench    # 描画・負荷に関わる改修のときはこちら
```

- **静的検査がFAILなら修正するまでpushしない。**
- スモークがSKIP（Playwright未導入/ブラウザ起動不可）の場合は、push後にCI（`.github/workflows/verify.yml` のsmokeジョブ）が通ることを確認する。
- アセット監査のWARNは破壊的ではないが、放置せずユーザーに報告する。

### 2. ベンチのbefore/after（描画系改修のみ）

- 改修**前**のコミットで `npm run preflight:bench` → 数値を控える。
- 改修**後**に再実行 → 出力される「BENCHMARKS.md への追記用ブロック」をBENCHMARKS.mdに追記。
- draw calls / geometries / textures が大きく増えた場合（目安: +10%以上）は理由を説明し、意図しない増加なら修正する。

### 3. 自動化できない確認項目をユーザーに渡す

pushの報告時に、今回の変更に応じた**実機確認リスト**を必ず添える。定番項目:

- [ ] 公開URLが更新されたか（キャッシュ回避 `?v=コミットハッシュ`）
- [ ] タッチ操作（ジョイスティック移動＋視点ドラッグの同時操作）
- [ ] 音（今回触った効果音/BGM/環境音のON/OFF・実機音量）
- [ ] 変更したモードの通しプレイ（開始→終了/クリアまで）
- [ ] 季節×時刻の切替（変更が視覚系のとき: 春夏秋冬×昼夕夜のうち関係する組合せ）
- [ ] 低スペック端末での体感（変更が負荷系のとき）

### 4. push前の最終チェック

- [ ] `git fetch origin` 済みで、origin/main との衝突がない
- [ ] コミットメッセージが既存慣行（`波X:` / `feat:` / `fix:` / `perf:`）に沿っている
- [ ] main へ直接pushしていない（mainはPages自動デプロイ直結）
- [ ] 大きい生アセット（>5MB）を誤ってコミットしていない（プリフライトのアセット監査で検出される）

## 判断基準

- 「文言だけの修正だからスモーク不要」→ `node scripts/preflight.js --no-smoke` までは省略可。**verify-htmlの省略は不可**（過去にID重複・参照欠落で起動不能が起きている）。
- 検証で直せない環境要因（CIのみで再現等）は、憶測で直さずログを添えてユーザーに報告する。
