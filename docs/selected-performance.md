# 表紙・入力・描画と端末測定

対象: 1、2、8、113、114、141、142、143、147。146の実測と資源解放は `selected-memory.md`。

## 画面と入力

- 表紙は復習期日、図鑑の発見、絵巻の進行から次の一つを推薦する。物語を含む遊びを最大4つ、端末内の設定で固定できる。
- 表紙へ戻る際はモード終了処理、入力解除、音とカメラ・HUDの復元を行う。ページ再読込を使わない。旧モードの遅延EDカードは所有者を確認し、章開始/退出時にタイマーを破棄する。
- タッチの移動・調べる・攻撃・ガード・回避・ロックをドラッグ/矢印キーで配置し、画面比率で保存。画面回転時は内側へ収める。取り消しと初期位置復元も備える。
- ガード/早歩きを長押し・切替から選べる。切替状態は中断、モード移動、タブを離れた時に解除。早歩き切替は散策・クイズ・日常体験・垣間見に適用し、退治のShift操作を保持する。
- 探索パネルはモード切替時に同期して閉じる。端末測定と配置編集のモーダルはTab循環とEscapeに対応する。

## 描画

建築と動かない調度を材質・項目・所有する親・空間範囲でまとめる。既存のインスタンスの行列も反映し、動く扉、御簾、蓋、腕・脚・頭、季節や人物リグは除外する。項目IDを保ち、当たり判定用の元モデルを残す。`?nobatch=1` の切り分け経路も維持する。

省電力時は遠い柱などの円柱・球の分割数を下げる。変形済みの布、植物、屋根は既存の専用LODに任せる。12m以内と図鑑の模型閲覧では元の形に戻す。元の形を破棄せず、低詳細形状は再利用する。

専用検査の同一シーン・同一カメラで、今回の結合のみ無効→有効は **2,419→2,204描画（215回削減）**。省電力用の85形状で **5,546三角形** を削減し、図鑑で完全に復元することを確認。顔のように頂点を変形した共有形状は除外する。FPSや消費電力の改善をこの描画回数から断定しない。全更新前後の固定視点計測は別途記録する。

全更新前後の固定seed・1280×800・同じ4視点・GPU完了待ち32描画（最初の8回を除外）による比較も完了した。列のmsは描画処理の中央値で、操作・音・UIを含む実プレイFPSではない。

高設定の俯瞰では全更新を含め169回（約7.2%）減った。人物や接水演出の追加も含むため、結合だけの215回削減とは条件が異なる。元の当たり判定・模型閲覧と元形状への復帰を保持するため、scene内の形状バッファは約12.80→14.55MB（+1.74MB）。速度と形状保持のための固定追加資源であり、往復による増加は別のメモリ検査で確認した。

証跡は `artifacts/review/visual-selected-before.json` / `visual-selected-after.json`。正面・俯瞰・池・近景の前後画像を確認し、建物・庭の表示欠落は見つからなかった。計測は各設定1試行で、端末差や長時間の熱による変化を検証するものではない。

## iPhone / iPad

設定の「iPhone / iPad・端末の測定」から、機種名、1分/5分/15分、開始電池を入力して開始。散策を続けると描画間隔・描画回数・形状/テクスチャ数を集め、終了時に結果が開く。終了電池と触れた時の熱を入力しJSONを端末内へ保存する。外部送信は行わない。

結果には日時、機種、ブラウザ、画面寸法、測定秒数、FPS中央値、遅いフレームの95%、描画回数、資源数、タブ非表示による中断を含む。利用できないJS heapはnull。資源の個数をGPUメモリのバイト数として扱わず、表面温度と電池を推定しない。

**物理iPhone / iPadでの15分測定は未実施**。PCブラウザのモバイル表示・測定UI・保存機能の確認と区別する。実機では散策→俯瞰→退治→図鑑を同じ順序で行い、通常/省電力をそれぞれ測る。開始電池、画面輝度、充電の有無、室温と操作順を揃えると比較しやすい。
