# 再現モードの低い画面と操作UI

2026-10-15、origin/main bafc839統合後の新しい横向き検査で発見した問題を修正。アプリ側の変更は `src/app/app.css` のみ。本文・訳・注は省略せず、既存検査の閾値を変更しない。

## 原因

枕草子の第1・2段で上端のボタンを覆っていた要素は本文ではなく `#loadingScreen.show`。実際の `elementFromPoint` がz-index 120・pointer-events autoの読み込み画面を返した。enterModeの読み込み幕が約650ms残るため、開始直後だけ三つのボタンが覆われていた。

古今著聞集の第10段では和歌に必要な高さが181pxとなり、単列の訳・注・ナビと合算したパネルは高さ379.81px、上端2.19px。上部操作列の下端38pxを超えていた。`fitSaigenHonbun` の和歌の最小高さは守られていたが、パネル全体を収める縦の余裕がなかった。

origin/mainにも同じ読み込み画面のz-indexと単列の基本CSSがある。草庵のスタイルは訪問専用body classに限定されており、再現の通常画面に適用されない。

## 修正

再現中だけ読み込み幕を場面の手前・操作UIの奥（z-index 44）に置き、pointer-eventsをnoneにする。既存の再現専用準備幕と同じ扱いで、準備中も終了・目次・絵を見るを押せる。ほかのモードの読み込み画面は変更しない。意図的な題名・和歌の大写しは従来どおりクリックで閉じる演出であり、この検査ではそれを通常のAPIで閉じてから読み込み幕を検査する。

横向き・高さ520px以下は、本文を左、現代語訳と注を右に配置。話者と段の移動ボタンは両列にまたがる。844×390では上部操作列とパネルの間が23pxになり、和歌は12pxのまま全文が見える。高さ340px以下だけ散文の余白・文字サイズと訳の行間を調整し、568×320でも長文が操作列へ重ならないようにした。縦向きで長い和歌が23px切れる既存の問題も確認したため、和歌の枠だけ192pxとし、散文の枠は変更しない。
