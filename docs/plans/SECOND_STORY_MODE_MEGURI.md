## 0. 一行コンセプト

**勝負のつかぬ歌合の一夜が、明けても明けても巡り続ける。判者となった蓮は、年中行事の景物の"ズレ"を手がかりに、時を縛る一首の未練を読み解き、返し歌でループを解く。**

これは、当初アイデアA「歌争ひ（歌合の対話劇）」とB「移ろひの記（年中行事ループミステリー）」を **「和歌を正しく読む」という単一の芯** で統合したものである。AとBは別々の企画に見えて、次の一点で必然的に結びつく――**歌合とは歌の景物（季語・掛詞・本歌）を読む競技であり、ループのズレとは景物と実景の齟齬である**。だから「歌を読む力」がそのまま「ループを解く力」になる。

## 1. 第1モードとの対（つい）の構造

| | 第1モード「御簾の向こうへ」 | 第2モード「巡り歌合」 |
|---|---|---|
| 時間構造 | **直線**：春→夏→秋→冬→常世→春（季節を1周して現実へ還る） | **円環**：同じ一夜がループする（螺旋状に真相へ近づく） |
| 学ぶ対象 | 建築・建具・作法（**空間**の名） | 和歌・修辞・景物（**時間**と**言葉**の名） |
| 主人公の課題 | 名を知らぬ邸で「生き延びる作法」 | 歌を読めぬ宴で「時を解く読み」 |
| 恐怖の型 | 懐かしいのに帰れない（同化） | 抜け出せない反復（永劫回帰） |
| 中核テーマ（バイブル） | ②見えない相手を理想化しない | ③言葉は呪いにも救いにもなる（歌が時を縛り、歌が解く） |

第1モードで **建具の名** を学んだ時任蓮が、第2モードでは **歌の読み** を学ぶ。学習対象が空間から言語へ進む続編として、教材的にも接続する。

## 2. 物語の芯

### 舞台
邸で「歌合」が催される一夜。時任蓮（=秀頼）は、歌が読めぬまま **判者（勝敗を裁く役）** に据えられてしまう。左方・右方の歌人が番（つがい）ごとに歌を競い、判者が勝ちを定める。

### ループの動力
歌合の **最後の一番** が、どうしても決着しない。夜明けの鶏が鳴くと、一夜は巻き戻り、また宵の口から始まる。プレイヤーの体感では「判定を誤る」または「真相に触れぬまま夜が明ける」とループする。

### ズレ（Bの要素）
巡るたびに、邸の **年中行事の景物が少しずつズレる**。
- 桜が散らないまま雪が降る／灯籠が川を逆さに上る／月が二つ懸かる／七夕の梶の葉に歌が先に書かれている。
- これらは偶然ではなく、**時を縛る一首に詠み込まれた景物**が現実の景を侵食した痕跡。プレイヤーは「歌の景物」と「実景」の齟齬を **垣間見（観察）** で見つける。

### 真相（Bの謎＝Aの歌）
歌合の最後の番で、ある歌人――**負けを認められぬまま詠み切れなかった女房**――の一首が、宙に浮いたまま時を縛っている。彼女は「返してもらえなかった歌」を抱えて、判定を永遠に先延ばしにしている。

### 解法（A×#8の統合）
プレイヤーは、集めたズレ＝景物から、その未練の歌の **掛詞・縁語・本歌** を読み解く（ここで `src/app/waka-notes.js` の `gihō` データが判定材料になる＝#8の初の実用先）。技法を正しく読み切ると、彼女の本心が見える。最後に、彼女の歌への **返し歌** を選ぶ／詠むことで、番に決着がつき、ループが解ける。

> テーマ接続：勝ち負けを裁くこと（判者）ではなく、**相手の歌を最後まで読み、返すこと**が時を進める。「相手を勝手に物語にしない」（バイブル②）＝負けた歌人の未練を決めつけず、歌の技法から本心を読む。「言葉は呪いにも救いにも」（バイブル③）＝返されなかった歌が時を呪縛し、返し歌が解く。

## 4. エンジン接続設計（既存システムへ正確に載せる）

第2モードは **新しいイベント`type`をほぼ増やさず**、既存の枠で表現できる。以下は棚卸し（2026-07-12）で確認した既存機構への写像。

### 4.1 再利用する既存機構
- **歌合ミニゲーム**：`gameMode: "utakai_story"` を拡張し `"utakai_meguri"` を追加。判定ロジック本体は `story_runtime.js` の歌合実装を流用（`APP.storyUtakaiFullDeck` で `WAKA_DATA` 全開放）。番の勝敗集計 `(ok, wins)` のコールバック形式もそのまま。
- **和歌データ**：`src/app/waka.js` の `WAKA_DATA`（季節別配置）を対戦札に使用。**技法判定は `src/app/waka-notes.js` の `gihō`**（掛詞/縁語/本歌取り）を参照＝#8の実用。
- **季節・時刻・天候**：`set_scene` の `season`/`timeOfDay` 上書き＋`effect` で「ズレ」を演出（既存の季節システムをそのまま流用。新規描画不要）。
- **観察（ズレ発見）**：ch3の垣間見 `kaimami_story` を流用し `kaimami_zure` に。観察対象を「人」から「景物」に変えるだけ。
- **舞台演出**：`stage` オブジェクト。既存フィールド `judgeFanText`（題）・`silence`・`erosionLevel` を再利用。
- **導入様式**：各巡回の冒頭は第1モード同様「小萩独白×4」の様式を踏襲（統一感）。
- **ED判定**：`ending_check` + `determineEnding()` の既存分岐機構を流用（新パラメータは `effects` の `additionalProperties` の器に載る）。

### 4.2 新規に必要な最小実装（Opus実装対象）
1. `gameMode: "utakai_meguri"`（`utakai_story` の派生。最後の番だけ「返し歌選択」フェーズを追加）。
2. `gameMode: "kaimami_zure"`（`kaimami_story` の派生。景物ズレの観察）。
3. `stage` 新フィールド：`loopIndex`（巡回数）・`seasonMismatch`（ズレ演出キー。例 `"sakura_in_snow"`）。既存の `stage` ブリッジに数行追加。
4. ループ制御フラグ（下記4.3）を `determineEnding` の分岐に追加。

新イベント`type`は不要（`trigger_minigame`/`flag_branch`/`ending_check`/`set_scene`/`effect` で足りる）。

### 4.3 パラメータ／ルートフラグ設計
既存の三値 **現(realityEgo)／雅(fantasySynchro)／蝕(brainErosion)** を流用しつつ、ループ固有の数値フラグを `effects` の器（`additionalProperties:true`）で加算する。

| フラグ | 型 | 意味 | 立つ契機 |
|---|---|---|---|
| `meguriCount` | number | 巡回した回数 | 各ループ頭で+1 |
| `zureFound` | number | 見つけたズレの数（最大4） | `kaimami_zure` 成功ごと+1 |
| `yomiSolved` | number | 読み解いた技法の数 | 掛詞/縁語/本歌の各正答+1 |
| `kaeshiChosen` | string | 選んだ返し歌の態度 | 最終フェーズの選択 |
| `judgedFairly` | bool | 番の判定を私情でなく歌で下したか | 各番の判定選択 |

### 4.4 ED設計（determineEnding への追加分岐）
第1モードのED1〜5とは別系統の4結末。判定は既存 `ending_check` の要件方式に載せる。

| ED | 条件（設計値・要調整） | 結末 |
|---|---|---|
| **真** 「明けの歌」 | `zureFound>=4` ∧ `yomiSolved>=3` ∧ `kaeshiChosen="返す"` ∧ 雅≥50 | 返し歌が届き、詠み人が名を取り戻して番に決着。夜が本当に明ける |
| **和** 「引き分けの宵」 | ズレ・読みが一部のみ、返し歌は無難 | ループは解けるが詠み人の名は分からぬまま。穏やかな幕 |
| **呪** 「詠み残し」 | `kaeshiChosen="裁く"`（歌でなく勝敗で押し切る） | 番は決したが未練は残り、別の景物で新たなループが始まる暗示（Bad） |
| **蝕** 「百夜一夜」 | 蝕≥100 ∨ `meguriCount` 過多で惰性ループ | 判者が景物の一部と化し、宴の絵の中に溶ける（第1モードED5と対のSpooky） |

## 5. シーン構成（章＝1巡ではなく「螺旋」）

物理的な章ファイルは第1モード同様 `story/chapters/` に置くが、内部は「巡回」を `flag_branch(meguriCount)` で分岐させ、同一シーンを状態違いで再訪する螺旋構造にする。

1. **宵の口（共通・小萩独白×4）** ― 判者に据えられる。歌合の作法説明（=教材：番／方人／講師／判詞）。
2. **第一〜三番の判定** ― `utakai_meguri`。私情か歌かで `judgedFairly` が動く。
3. **最後の番、決着せず** ― 詠み人の一首が宙に浮く。鶏鳴。夜明けフェード。
4. **巡回（loop）** ― `set_scene` で景物がズレて再開。`kaimami_zure` でズレを拾う。巡るごとに小萩の独白が真相に近づく（第1モードの回想連鎖と同型の技法）。
5. **読みの累積** ― `zureFound` が閾値に達すると、`waka-notes.js` の `gihō` を使った技法当て（掛詞/縁語/本歌）。
6. **返し歌** ― 詠み人の未練の歌に、どう返すかの選択（`kaeshiChosen`）。
7. **結** ― `ending_check` → 4結末。

## 6. 教材設計（国語科としての芯）

- **可視化しにくい修辞を"体験"に変える**：掛詞は「一語が二つの景を同時に指す」ことをズレ演出で体感させる（例：「ながめ」＝長雨と眺め→雨の景と物思いが二重写しになる巡回）。`waka-notes.js` の `gihō.detail` がそのまま解説になる。
- **本歌取り**：ズレた景が「どの本歌の景か」を当てる＝出典（`shutten`/`raireki`）を辿る学習。持統天皇歌の万葉原歌との異同（`waka-notes.js` 収録）が格好の教材。
- **歌合という文化装置**：番・方人・判詞・持（引き分け）といった歌合の語彙を、判者体験を通じて学ぶ。
- **評価の主観性**：「歌で裁く／私情で裁く」の選択（`judgedFairly`）自体が、批評とは何かを問う。

## 8. リスクと判断

- **既存モードを壊さない**：第2モードは新 `gameMode`/新フラグで隔離。既存ch1〜6の `determineEnding` 分岐には触れず、第2モード用の判定を別要件で追加する。
- **単一HTML方針の維持**：新規外部アセットは増やさない。景物ズレは既存の季節/天候システムの再利用のみ。
- **スコープの誘惑**：フル実装は大きい。**P0〜P2（設計・脚本・データ）はモデルの生成質が焼き込まれる"静的資産"なので上位モデルで作り切り、P3（エンジン実装）はパターンが決まっているためOpusに委譲**する、という配分が費用対効果最大。
