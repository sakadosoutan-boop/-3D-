## 実装原則

1. 新機能追加より先に、正本ドキュメント、性能、入力、保存、公開検証を固める。
2. 学習教材としての主導線を作り、戦闘・恋愛・占いは「任意の深掘り」として整理する。
3. 配布物は単一HTMLを維持してよいが、開発は分割ソースから統合する。
4. 既存の座位人物、物語導線、恋愛シミュレーション、退治モードを巻き戻さない。
5. 各フェーズは `npm test` に加え、必要な専用検証を増やしてから完了扱いにする。

## Phase 1: 性能予算と軽量化

目的: 機能追加に耐える描画予算を作る。

- [x] `npm run benchmark` を package.json に追加し、`scripts/collect-benchmark.js` を正規検証へ昇格。
- [x] Playwright計測の乱数を固定し、代表フレームを `renderer.info.reset()` 後に1回描画して記録する。
- [x] PC相当の自由散策・春昼で draw calls、triangles、geometries、textures を記録。
- [x] 目標値を設定: まず自由散策・春昼で draw calls 1,200以下、geometries 2,000以下を目標にする。
- [x] 植栽の第一段軽量化: 松/落葉樹の葉叢を `InstancedMesh` 化し、松葉・椿・薄・前栽を影自動付与から外す。
- [x] 共通 `box()` / `cyl()` のジオメトリキャッシュで geometry 数を 2,000以下へ削減。
- [x] 高欄と静的建築/竹/藤/庭の一部を `InstancedMesh` バッチ化。
- 反復物を優先して `InstancedMesh` 化: 格子、簀子板、前栽、石、札、灯籠、竹、藤房、桜花びらの一部。
- 影の付与を中央管理化し、装飾小物と遠景の `castShadow` を原則オフ。
- GLBの読み込みタイミングをモード別遅延ロードへ寄せる。ボス/大型モデルは必要な場面だけ。

完了条件:
- benchmark差分が docs/metrics に追記され、目標に近づいたことが数値で見える。
- smokeで物語/退治/恋愛/占いの表示が維持される。

## Phase 3: 入力・衝突・保存の基盤化

目的: 今後のモード追加で破綻しない操作と状態管理にする。

- `InputManager` を作り、移動/視点/攻撃/回避/調べる/決定/戻るをアクション名で扱う。
- 既存の `keys.w || keys.arrowup` 直書きを段階的に置換する。
- キーボードリバインドとタッチ操作の対応表をlocalStorageへ保存。
- 衝突判定を `CollisionWorld` として整理し、池/外周/建物/柱/家具/モード専用障害物を一元管理する。
- localStorageキー一覧、スキーマ、移行関数、破損時リセット方針を `docs/handbook/STORAGE.md` に作る。
- Story/Renai/Codex/Progressの保存ロードを簡易単体テスト化する。

完了条件:
- 入力設定を変えても散策、退治、牛車、物語が動く。
- セーブ破損時に白画面化せず、復旧導線が出る。

## Phase 4: 各モードのゲーム性強化

目的: 既存モードを「触れるだけ」から「もう一度遊ぶ」へ上げる。

- クイズ: 正解時カメラ寄せ、誤答差分解説、苦手分類分析、復習セット、ゴーストタイム。
- 垣間見: 従者の顔向き/足音/扇の予兆、見つかった理由の短いリプレイ説明。
- 物の怪退治: ボス別予兆、攻撃テンポ差、ロック対象、軽いヒットストップ、スマホ操作の再検証。
- 歌合: 判者の好みの匂わせ、選歌相性表示、判詞の教材化。
- 牛車運び: 曲がり角、速度、積荷、車寄せ精度、恋愛/一日体験との接続。
- 占い: 吉方/凶方が恋愛、牛車、物語サブイベント、散策発見率に反映されるようにする。
- 恋愛シミュレーション: 対象女性ごとの差、行事、贈り物、文の配達、装束、怪異調査を段階追加。

完了条件:
- 各モードに成功理由/失敗理由/再挑戦理由が表示される。
- 物語・恋愛・散策の報酬が互いに戻る。

## Phase 5: 物語の製品化

目的: 「デモ版」から正式モードへ格上げする。

- 「デモ版」表記を外すか、「第一部」など正式名称へ置換。
- ED分岐ゲージを、ED後だけでなく章中の予兆として段階解放する。
- True End条件を章メニュー・手動記録・結果画面で納得できるように説明する。
- 第6話のED演出をさらに差別化し、ED到達後の隠し演出や称号を強化。
- 小萩/栞、右近、左大臣、判者の表情/所作差分を増やす。

完了条件:
- 物語だけを遊んでも1本のゲームとして成立する。
- ED1到達に失敗しても、次に何を変えればよいかが明確。

## Phase 6: 教材/公開品質

目的: 学校・展示・公開URLで安心して見せられる状態にする。

- 教材モード、展示モード、通常ゲームモードを分ける。
- 参照資料リストを整備: PDF本体は除外しても、出典、版、閲覧URL、参照箇所メモは残す。
- 音源/GLB/生成素材のクレジットとライセンス欄を一本化。
- 公開URLの定期検証、Pagesデプロイ後のキャッシュ確認を手順化。
- ビジュアル回帰スクリーンショットを導入し、スマホ縦/横、PCで主要画面の崩れを検出する。

完了条件:
- READMEから教材利用者、開発者、プレイヤーが迷わず入口を選べる。
- 第三者が素材由来と現行仕様を検証できる。

## 優先順位まとめ
