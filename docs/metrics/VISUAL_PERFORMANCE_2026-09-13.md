# 見た目の改善と描画負荷の比較 — 2026-09-13

基準は `c97434f`。今回の変更は既存のテクスチャ生成、UV、色、霧の係数に限定した。

## 改善内容

- 俯瞰だけ霧の密度を調整し、屋敷と庭の配置が見えるようにした。散策視点と退治モードの霧は従来どおり。
- 雲のUVを平射図法に変更し、地平付近で縦筋に伸びる問題を修正。時間帯ごとの色と不透明度も調整。
- 白砂の大きくうねる溝と強い明暗を抑え、砂粒・箒目を小さな尺度に調整。
- 柱・床の木目を細かくし、目地のコントラストを抑えた。
- 床・砂の法線マップとAOの強さを調整。既存の解像度と生成枚数は維持。
- 霞を薄くすると見えていた外周地面の端を、同じ4頂点・2三角形の平面の延長で隠した。草の模様の尺度も維持。

モデル・材質・照明・描画パスを追加していない。雲の投影と草のUV計算は起動時のみ。HTMLは5,921,457バイトから5,921,912バイト（+455バイト）になった。

## 計測方法

`npm run benchmark:visual -- LABEL [HTML_PATH]` で再計測できる。PlaywrightとChromeが必要。出力は `artifacts/review/visual-LABEL.json` と高画質の画面画像。

- Windows上のChrome headless、1280×800、同一環境。
- 同じ乱数シード・カメラ・時間帯・季節・アニメーション時刻を使用。オンライン通信と適応画質を停止。
- 高画質：タッチ判定なし、DPR 1、影1024、法線マップとAOあり。
- 低消費電力：タッチ判定あり、DPR 0.56、影なし、法線マップとAOなし。スマホ実機ではなくブラウザで設定を再現。
- ブルームは両版ともオフ。描画条件を固定し、アニメーションを停止して `renderer.render` から `gl.finish()` まで計測する。
- 各場面32フレーム描画し、先頭8回を除外。残る24回の中央値を記録。変更前・変更後それぞれ3回ずつ起動し、下表は各回の中央値の中央値。最後の組は実行順を逆転。
- 遅延生成されるマップの読み込みを待ち、シーン全体のテクスチャ画素数が全測定で一致することも確認。

## 結果

値は1回の描画に要したミリ秒。ゲーム全体のFPSや入力処理時間ではない。

| 設定 | 場面 | 変更前 | 変更後 |
|---|---|---:|---:|
| 高画質 | 正面・昼 | 15.4 | 15.4 |
| 高画質 | 俯瞰・昼 | 29.9 | 29.2 |
| 高画質 | 室内・昼 | 15.9 | 15.8 |
| 高画質 | 庭・夕方 | 10.7 | 10.0 |
| 高画質 | 正面・夜 | 15.2 | 14.7 |
| 低消費電力 | 正面・昼 | 21.6 | 16.7 |
| 低消費電力 | 俯瞰・昼 | 26.8 | 27.0 |
| 低消費電力 | 室内・昼 | 13.9 | 14.0 |
| 低消費電力 | 庭・夕方 | 9.1 | 9.1 |
| 低消費電力 | 正面・夜 | 16.4 | 15.6 |

増加した2条件の差は0.1〜0.2msで、各条件の試行間変動より小さい。今回の条件では明確な描画時間の悪化は確認されなかった。低消費電力の正面などは試行間のばらつきが大きく、この結果を高速化率の保証には用いない。

全10条件・各3回について、変更前後のdraw calls、三角形数、生成済みジオメトリ数・テクスチャ数、ジオメトリの配列バイト数、シーンのテクスチャ総画素数、シェーダープログラム数、画質設定が一致した。例：高画質の俯瞰は両版とも3,948 draw calls、293,384三角形。シーンのジオメトリ配列は5,366,826バイト、テクスチャ総画素数は高画質15,618,080・低消費電力14,929,952で変わらない。これらは構造の比較であり、ブラウザ全体のRAMや実GPU使用メモリの直接測定ではない。

各試行の値と一致を確認した項目は [JSON記録](VISUAL_PERFORMANCE_2026-09-13.json) に保存した。最初の試走は端末のタッチ判定が高画質にも残っていたため、この集計から除外している。
