## 改善した見た目

- 春の白砂に出ていた大きな七角形の白い塊を、小さな花びらに修正。舞い散る桜の既存画像を再利用した。
- 落ち花を色ごとの2バッチにまとめた。計測用シードでは113個の個別メッシュが2個のInstancedMeshになる。小さな落ち花は影を落とさず、周囲の影は受ける。
- 漆喰壁の斑点を細かく薄くし、汚れに見える強い凹凸と陰影を抑えた。
- 檜皮屋根の黒い横筋と縦の刻みを弱め、面全体の細かな質感を整えた。
- 池を少し落ち着いた青緑にし、波の白い筋と強い反射を抑えた。
- 夜の既存の環境光・室内光・露出を小幅に調整し、建物の輪郭と床を見やすくした。
- 散策時の画面周辺の暗さを軽くした。退治モードの周辺効果は維持。

新しい画像・照明・後処理パスは追加していない。画像解像度・生成ループ数は従来どおり。CSSは `src/app/app.css` を編集し、`build-app` でHTMLに同期した。

## 負荷の比較

Chrome headless、1280×800、固定乱数・固定視点・固定時刻。高画質（DPR 1、影1024、法線マップ・AOあり）と低消費電力（DPR 0.56、影なし、法線マップ・AOなし）の5場面を測定した。自動画質とブルームは両版とも停止。

ブラウザを各回起動し直し、同時に開くゲームを1個に限定した。各場面32回描画し、最初の8回を除いた24回の中央値を記録。変更前後を各3回測定し、表は3回の中央値。順序は「前→後→後→前→前→後」。測定中のスクリーンショット保存は停止し、画面確認を分けた。

## 比較方法の切り分け

途中で試した「同時に2つのゲームを開き、交互に描画する」方式では、後に開いた高画質画面が約5〜13%遅く見えた。同じ変更前ファイルを2回開く対照実験でも、正面13.7%・俯瞰14.6%の差が出たため、この方式は変更の評価に使わなかった。最終表は単独起動による再測定だけを使用している。

再計測は `npm run benchmark:visual -- LABEL BASELINE_HTML` と `npm run benchmark:visual -- LABEL`。`VISUAL_NO_SCREENSHOTS=1` を指定すると画像保存を省略できる。遅延生成される最後の法線マップ・AOを待ち、インスタンス配置配列と影の有効状態も記録するよう計測スクリプトを補強した。

実機スマホ、全モードの長時間プレイ、起動時間の性能比較までは検証していない。
