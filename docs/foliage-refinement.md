# 平安庭園の枝葉接続

正本は `src/app/visual-experience.js`。HTMLへの反映・ブラウザ検証は親の統合工程で行う。徒然草第七段の再現モードの `TSURE_TREES` を参考に、枝の終端に葉の房を配置する設計、楓の対生、七つの細長い裂片、葉柄、木と葉の共同風変形を取り入れた。徒然草のソースは変更しない。

## 造形

従来は八つの樹冠中心の周りへ三枚交差の葉を球殻状に配置していた。単葉の中心ではなく葉柄の根元を基準とし、既存 `crownTips` → 短枝 → 葉柄 → 葉身の順に接続する。既存の幹から樹冠中心へ伸びる枝を再利用する。

楓は深い七裂の単葉と七本の淡い葉脈。凹形の輪郭は三角形分割で穴を横断しない。椿は折れた主脈を持つ楕円形の常緑葉。各短枝は楓三対＋先端一枚、椿六枚を持つ。楓と椿の葉身・小枝はそれぞれ共有geometryで、各木の近景は32房（楓224葉／椿192葉）を二つのInstancedMeshへまとめる。材質・テクスチャは房ごとに追加しない。

補助の樹冠塊は元の配置から65%へ縮め、冬の楓では非表示にする。葉を塊の中へ全部隠さず、外側の葉も葉柄と短枝で木へ接続する。椿の既存45花の配置行列と季節表示は維持する。

## 風・冬・LOD

短枝と葉は同じ起点・同じインスタンス行列・同じ風のuniformを使う。短枝の原点では風の重みが0になり、幹の枝先から離れない。葉身の小さな揺れは葉柄末端を支点とするため、その基部は動かない。風を止める省電力・動きを減らす設定にも従う。

冬の楓は葉身と補助樹冠を隠し、枝だけを残す。椿は葉と花を維持する。葉と小枝の雪は上向きの面の着色のみとし、葉身の基部だけを法線方向へ押し出して葉柄から離す処理を避ける。

近景32房、中景16房、省電力・低画質8房、遠景0房。各prefixは八つの枝先をすべて含むため、LODで片側の枝だけ消えない。距離は約19m/43mで切り替え、復帰は16m/39mとして境界の点滅を抑える。省電力は30m以内だけ8房。遠景は既存の低分割樹冠を使う。切替はcountとvisibleのみで、geometry・texture・配置行列を作り直さない。

公開APIは `ESTATE_FOLIAGE.attach(root,{maple,material,woodMaterial})`、`fitBounds(handles)`、`selectLOD(...)` と `VISUAL_EXPERIENCE.foliageSprays/updateFoliageLOD(viewCamera)`。鎌倉の現行植栽は松なので変更しない。

図鑑は通常animateの更新を止めるため、各panelのrender直前に `updateFoliageLOD(viewCamera,panel.roots)` を呼ぶ。第二引数を渡すと、そのroot自身または子孫の木だけを近景32房に固定する。省電力でも閲覧対象の形状を維持し、無関係な木のvisible/countは変更せず模型のmaskを保つ。冬の楓の落葉は維持する。空配列は何も変更しない。closeで第二引数を省略した `updateFoliageLOD(camera)` を呼び、通常の距離・省電力LODへ戻る。描画中に全木のLODを戻してmaskを解除することはしない。

椿の花は本体の `SEASONAL.tsubakiFlowers` 一つに3本×15輪の順で配置され、木のrootとは別にworldが所有する。図鑑の単体/比較パネルでは、選択した木の範囲だけを同じbatchの先頭へ一時的に移して描画する。CPUの行列snapshot（45×16 float、約2.8KiB）とcount/visibleを退避し、各drawのfinallyで完全に戻す。既存の季節表示を尊重し、夏に花を強制表示しない。周囲表示は元の45輪を描画する。追加Mesh/geometry/material/textureを生成せず、写真タブ・閉じる・描画例外時にも一時配置を残さない。

## 描画予算と検証

追加写真・画像テクスチャ0。各木の葉の描画は従来1callから葉身＋小枝2callsへ変わる。楓/椿の共有geometryは計4個で、葉が何百枚あっても描画callは増えない。近景の三角形数は葉身・葉脈・小枝を合わせ、楓9,952（旧10,752）、椿4,352（旧5,760）。影を落とすパスは追加しない。

`node scripts/foliage-refinement-test.cjs` は同梱Three r128と本体の実際の `broadleaf` 生成関数を使用する。2026-10-13のCPU検証は13判定成功。枝先との起点誤差、葉柄終端と葉身基部の誤差は1e-6m未満。単葉shape、共有資源、有限座標、全インスタンスを含むbounds、冬の落葉/常緑、繰返しLOD、三角形予算、図鑑の対象限定と無関係なmask保持を検査した。

親のbuild後に `node scripts/foliage-refinement-playwright.cjs` を実行する。実際の散策開始と季節/画質操作で近景の楓・冬椿を描画し、GLSLコンパイルエラー0、共同wind、葉柄支点、冬の楓/椿と花、近/中/遠/ecoの32/16/0/8房、通常復帰32房を検査する。四季×三距離を20反復し、葉のgeometry/material IDと花の配置を比較する。近景PNG2枚とJSONを `artifacts/foliage-refinement` へ保存する。

花の図鑑検査は実モデル3本を順に選び、実際の `CODEX_VIEWER.open/compare/render/close` と描画を使用する。描画直前の行列・count・visibleを記録し、対象15輪が正しい元範囲に一致すること、非対象パネルでは花が隠れること、周囲表示は45輪であることを検査する。各木6反復で比較の左右・写真切替・閉じる後の復元と資源ID保持を確認し、rendererへ意図的に描画例外を注入した経路でも実装のfinallyによる復元を確認する。夏の非表示も検査する。2026-10-13の統合後ブラウザ検査ですべて合格。

統合担当が近景PNGと全体構図を確認し、shader例外0、通常/低画質/省電力の境界付近での葉数復帰、20反復の季節/LODと図鑑検査を確認した。通常LODの履歴は一時的な低画質/省電力/図鑑表示とは分けて保持する。実機FPSは別の計測であり、iPhone/iPadでは未測定。

既存のvisual-experience検査は旧表示の `mesh.count>=100` を葉数の判定に使っている。新表示は一房に複数葉をまとめるため、実際の葉数は `mesh.count*mesh.geometry.userData.leavesPerShoot`、最大葉数は `mesh.userData.leafCount` で確認する。
